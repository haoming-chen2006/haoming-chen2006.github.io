# NOTES-ui — Hollowmere UI (BG3-style overlay)

Owner: ui agent. Everything under `src/ui/**`, `public/assets/fonts/**`, `public/assets/ui/**`, `dev-ui.html`, and the `#loading` markup in `index.html`.

## Wiring (lead)

```ts
import { createUI } from './ui/index.ts';
const ui = createUI({ world: game.world, game });      // game satisfies UIGame: pause/setQuality/quality/input/restart/startGame/cam
game.frameHooks.push((dt) => ui.update(dt));           // once per render frame (HUD bars, floating text, boss bar, cooldown sweeps)
ui.showScreen('menu');                                 // after the loading screen hides
// dialogue runtime: ui.dialogue.present(node, choices, onPick, onContinue) / ui.dialogue.hide() / ui.dialogue.showRoll(roll, onDone)
// quest runtime:    ui.tutorial.show(step) / ui.tutorial.complete(id) / ui.tutorial.card(title, html, keys?)
```

Optional second argument `createUI(ctx, { hotkeys, root, instantText })`:
- `hotkeys` (default `true`): the UI itself listens (capture phase) for **Esc / I / C / J / M** and toggles pause / inventory / character / journal / map, and for **1–9 / Space / Enter / arrows** while a dialogue or dice overlay is open. If game.ts prefers to route those keys via `input.wasPressed(...)` → `ui.showScreen(...)`, pass `hotkeys: false` so they don't double-toggle. Screens are only opened by hotkeys when `game.state === 'playing'` (or `state` is undefined).
- `instantText`: skip the dialogue typewriter.

`UI` also exposes (beyond the contract): `screen` (current `ScreenName`), `toast(text, kind)`, `subtitle(speakerId, text)`, `root`, `warm()` (pre-compiles the dice renderer; it is called automatically ~2.5 s after creation on idle — call it earlier from the loading screen if you like).

### What the UI does with input / pause
- Any open screen: `game.pause(true)` (except `menu | classSelect | credits | death | ending`, which capture input but do not pause), `input.uiCapture = true`, `input.releaseLock()`.
- Closing the last screen: `pause(false)`, `uiCapture = false`, `input.requestLock()` (only if `game.state === 'playing'` / undefined).
- Dialogue and dice overlays: `uiCapture = true` + pointer lock released while open (choices are clickable); no pause. `isBlocking()` is true for screens, dialogue and dice.
- Class select `Begin` → `nav.close()` first (unpause / uncapture) → `game.startGame(classId, name)`. It also writes `localStorage['hm.save'] = {classId, name}`, which makes the **Continue** item appear on the main menu (Continue just calls `startGame` with those values). Pause → *Quit to menu* and death → *Main menu* clear that flag and call `game.restart()`.
- Death → **Rise again** calls `game.prologue.respawn()` (button reads *Rising…*), keeps asking every 400 ms until the `respawn` event closes the screen (the script only reads the request after its own fade-out and re-arms it there), falls back to `world.respawn()` after 1.8 s if nothing answers (a death outside a scripted encounter), closes regardless after 6 s; no prologue → `game.restart()`.
- Settings: quality → `game.setQuality(t)` (your implementation reloads); sensitivity / invert Y → `game.cam.sensitivity` / `.invertY`; volumes → `document.dispatchEvent(new CustomEvent('ui:volume', { detail: { master, music, sfx } }))`. Persisted in `localStorage['hm.settings']` and re-applied on `createUI` (so the audio agent gets an initial `ui:volume` on boot).
- `quality` low/medium → the root gets class `noblur` (panels drop `backdrop-filter`) and the dice skips the PMREM environment; keeps the SwiftShader harness fast and low-end GPUs happy.
- Backdrop blur is otherwise 6 px on panels only, never full-screen.

### Two DOM roots
`#ui` (z-index 10) holds the HUD, dialogue, dice and every screen except **death** and **ending**, which mount in `#ui-top` (z-index 95, created next to `#ui`). The game's fade-to-black element (game.ts, z-index 90) goes black 0.8 s after `death` and *before* `prologueComplete`, so inside `#ui` those two screens were invisible. Nothing else lives above the fade.

## Bus events consumed
`damage heal miss parry attackRoll check damageMod stagger xp gold loot equip levelUp toast staminaEmpty interactable bossStart bossEnd death areaEnter cinematic rest questStep questLog respawn gameOver prologueComplete dialogueStart dialogueLine dialogueEnd ui condition`
- `attackRoll` floaters only for the player's own attacks (`18+5 = 23 vs AC 13 — HIT`); enemy attacks show only damage / MISS / DODGED / BLOCKED / PARRY.
- `damage` on the player: red hit-flash vignette + portrait shake + a `−N` floater; on others: type-coloured number with the damage-type glyph, `CRITICAL!` callout.
- `check` (player, `roll.kind === 'check'`) → the **d20 overlay** (`showRoll`), judged one tick later so dialogue rolls — which call `showRoll` themselves right after the event — are not shown twice. Saves and attack rolls stay floaters; NPC checks are ignored. The cache's Perception, the boulder's Athletics, the altar and the gate therefore get the full spin → total → SUCCESS/FAILURE screen; Space / click / E / Esc dismiss.
- `dialogueLine` **outside the panel** (companion barks; `speakerId` `'ilyra'`, narrator, anyone) → bottom-centre **subtitle** `Ilyra — text` for `max(3, 0.06·chars)` s (game time; frozen while the game is paused or the dice overlay is open, so a nat-20 reaction queued during a world check appears after the dice). The runtime emits the event and calls `present()` synchronously with the same text, so a line is judged one tick later against the last presented text. Lines queue (max 3, a new one shortens the current to 1.2 s). `dialogueStart` drops whatever is still queued (the speaker is now on the panel); a reaction emitted *during* a dialogue shows under the top letterbox instead. Companions are named by first name (`Ilyra —`); narrator lines are centred italic without a name; the subtitle moves above the letterbox in cinematics and above the boss bar while one is up (`#hud.cine` / `#hud.bossing` / `#hud.dialogue`).
- `levelUp` (player) → level-up screen ~1.4 s later (deferred while a dialogue / dice / other screen is open; skipped if `player.pendingLevelUps` is already 0, i.e. a dev skip resolved the choice). The header uses the level the sim announced (`rules.ts` bumps `level` before it emits). `death` (player) → death screen after 2.6 s if still dead. `gameOver {victory:false}` → death screen. `prologueComplete` → ending screen after 1.8 s (stats table from the payload; falls back to `world.stats`). `respawn` closes the death screen.
- `ui {screen}`: consumed (idempotent) **and** emitted on every `showScreen` — handlers must not call `showScreen` from it in a way that would loop (mine guards on `name === current`).
- `cinematic {on}`: letterbox bars + hides bars/hotbar/quest/prompt/tutorial/pickups/toasts (`#hud.cine`).
- `questStep` drives the bottom-right objective panel; the panel also polls `world.quest` (first step with `done !== true`) so it stays correct without events.

## DOM events dispatched (audio agent)
`document.dispatchEvent(new CustomEvent('ui:sfx', { detail }))` with `detail ∈ 'click' | 'hover' | 'open' | 'close' | 'dice' | 'success' | 'fail' | 'levelup' | 'loot' | 'equip'`, and `'ui:volume'` as above.

## World fields read (all optional-chained)
`world.player` (hp/maxHp/tempHp/stamina/level/xp/prof/abilities/ac/skillProfs/saveProfs/expertise/feats/conditions/resources/cooldowns/targetId/weapon/dead/pendingLevelUps), `world.playerId`, `world.actors` (companion `ilyra` or first `kind === 'companion'`; boss by `bossStart.actorId`), `world.inventory`, `world.gold`, `world.equipment`, `world.kit` (hotbar ids; falls back to `CLASSES[cls].kit`), `world.quest`, `world.flags` (unlocks `CODEX` entries in the journal; `world.journalEntries` / `world.lore` override if present), `world.stats`, `world.cinematic`, `player.maxResources` (if the sim adds it; else class `resources` are the maxima for the pips).
World methods called: `equip(itemId)`, `unequip(slot)`, `useItem(itemId)`, `removeItem(itemId, qty)` (Drop; `dropItem` preferred if it ever exists), `chooseLevelUp(id)`, `respawn()` (death-screen fallback only), `setPlayerClass` (only via `game.startGame`). Game fields: `game.paused` (subtitle clock), `game.prologue?.respawn()`.
Content tables: static imports of `content/classes.ts` (CLASSES, FEATS), `content/spells.ts` (ABILITIES), `content/items.ts` (ITEMS), `content/story.ts` (CODEX, ENDING_STATS_LABELS, STEPS in the dev page only); `src/ui/content.ts` keeps placeholders for any missing id and exports `setContent()` if you ever want to inject tables at runtime. Icon aliases for the content ids live in `src/ui/icons.ts: ALIAS` (`bolt` → the lightning `surge` glyph for Action Surge, `dash` → boot, `reckless` → fist, `ward` → shieldSpell…).

## Screens (`ui.showScreen(name)`)
`menu` · `classSelect` · `pause` · `inventory` · `character` · `journal` · `map` · `levelUp` · `settings` · `credits` · `death` · `ending` · `null`.
Inventory / character / journal / map share a tab bar (I / C / J / M switch between them, Esc or the same key closes). Settings and credits remember where they came from (menu or pause) for *Back*.
HUD: portrait + level badge, HP (with lag ghost + temp HP hatch + low-HP pulse and red vignette), stamina (flashes on `staminaEmpty`), spell-slot diamonds (blue) + class-resource diamonds (gold), conditions with timers and sweep, XP bar, companion mini-portrait (name follows the actor), 6-slot hotbar + potion slot (cooldown conic sweep, cost, greyed when unaffordable; clicking a slot synthesises the keypress), objective panel with key chips, interaction prompt (bottom 36 %), subtitles (bottom 150 px), boss bar, area title card, toasts (top), pickup cards (right, above the objective panel), floating combat text, letterbox, crosshair dot (only for staff/wand/crossbow wielders without lock-on), rest fade. HUD is scaled with CSS `zoom` between 1× (≤900 px tall) and 1.35×.
Dice: three.js icosahedron with a numbered canvas atlas; lands with the rolled face upright (orientation solved per face), then modifier chips (`d20 · 14 + 5 modifier + Guidance 3`), total, SUCCESS / FAILURE (or HIT / MISS for attacks), nat 20 / nat 1 callouts, advantage note. Space / click continues (or skips the tumble).
Dialogue: portrait (class icon for the player, crescent crest for Ilyra, book for the narrator, crown for the boss), speaker, typewriter (click / Space to complete), numbered choices with gold `[Skill]` tags, DC preview on hover **or keyboard selection**, tag icons for attack / leave / gold, `{name}` `{class}` substitution. Keys 1–9, W/S or arrows + Enter. `#dlg` covers the whole screen while open, so a click anywhere completes / continues the line.
Tutorial: right-side stack, `show(step)` / `complete(id)` (check + slide-out), `card(title, html, keys?)` info cards (auto-dismiss 14 s, X to close), `INFO_CARDS` (ability scores, checks, AC, proficiency, spell slots, rest, stamina, HP, advantage, lock-on) exported from `src/ui/index.ts` — call `ui.tutorial.card(INFO_CARDS.ac.title, INFO_CARDS.ac.html)` from the quest script when you want one.
Key glyphs: `kbd('Shift')`, `keys(['W','A','S','D'])` from `src/ui/dom.ts`; mouse buttons as `LMB / RMB / MMB / Wheel`.
Map: the canvas is absolutely positioned inside `.map-wrap` (a grid item's `max-height: 100%` did not resolve and the 604 px canvas overflowed the 662 px panel at 720p); it now fits with the legend visible at every viewport.

## Known issues / notes
- Headless SwiftShader starves CSS transitions/animations when the page is busy and the sim advances only ~0.04 s per wall second while screenshots are taken. A shot can therefore show a screen mid-fade (or a previous screen's ghost), and anything gated on sim time (`q.wait`, encounter starts, cooldowns) takes minutes. Verify state with `eval`, and freeze visuals before a shot with `document.getAnimations().forEach(a => { a.pause(); a.currentTime = 1500 })` (restore with `.play()`); real-time removals (toasts 3.9 s, pickups 4.7 s) outlive a capture only if `setTimeout` is scaled in the page. Playwright's `page.click` never settles on such a page — dispatch `el.click()` — and `waitForFunction` must poll on an interval, not rAF.
- Death screen: the sim's "death saving throw" flow is not exposed as events, so the three red pips are decorative; `respawn` closes the screen.
- The level-up HP gain shown is the average roll (`hitDie/2 + 1 + Con`); if `rules.ts` rolls it, the number may differ by a point or two.
- `chooseLevelUp(id)` is called with `levelUpChoices[i].id` from the class table; the screen closes immediately (no confirmation).
- Map: the crypt (z ≈ −500) is not drawn; the map says so when the player is down there.
- Fonts are variable-weight latin subsets (Cinzel 400–900, EB Garamond 400–800 + italic) at `/assets/fonts/*.woff2`, self-hosted via `@font-face` in `ui.css`; Vite rewrites them to `/rpgtrial/assets/fonts/...` in the build (verified).
- `public/assets/ui/` holds `corner.svg`, `divider.svg` and `icons.svg` (a `<symbol>` sprite of every icon in `src/ui/icons.ts`) for anyone who wants the same glyphs in 3D VFX or docs; the UI itself inlines them.

## Requests for the lead
- **Fade element vs. UI**: `game.ts` mounts the fade at z-index 90 above `#ui` (10). Death and ending now live in `#ui-top` (95) so they show over the black; if you ever want other screens above a fade, either lower the fade under `#ui` or tell me and I'll move more screens up.
- **`respawnRequested` (content agent, `deathFlow`)**: the flag is reset to `false` right after the fade-out, so a *Rise again* click during those 0.8 s was lost and the player waited for the 5 s auto-respawn behind black. The UI now re-requests every 400 ms, but dropping that reset (or reading the flag before the fade) would make the first click land. Deaths outside a scripted encounter (e.g. `damageActor('player', 999)` on the shore) never respawn from the script — the UI falls back to `world.respawn()` after 1.8 s.
- **`World.teleport()` state**: after a dev `prologue.skip()` the player can stay in state `interact` (fast-forwarded PickUp anim) or `jump` until sim time passes, and `interact` intent is ignored in those states (E did nothing next to Ilyra in the harness until sim time moved). Resetting `state` to idle inside `teleport()` (as the content notes already suggest for `jump`) would make skips and bot tests deterministic.
- **Dev skip + level-up**: fast-forwarding past the chapel resolves the level-up choice (`pendingLevelUps` 0) but the `levelUp` event still fires; the UI now refuses to open a screen with nothing to choose. `prologue.skip()` only works forwards — skipping back to `chapel` after `gate` spawns nothing (expected, just noting for harness writers).
- **Combat saves**: `check` events with `kind: 'save'` (enemy spells) stay floaters on purpose; if the sim ever emits player *skill* checks mid-combat they would open the blocking overlay — shout if that is a possibility and I'll gate on `player.targetId`/encounters.
